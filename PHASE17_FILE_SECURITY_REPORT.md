## 1. Executive Summary

This report assesses the file handling, path resolution, and asset serving mechanics within IELTS by GAMA. The embedded HTTP server and media storage pipelines were audited for directory traversal vulnerabilities (OWASP Top 10 A01/A05), file overwrite risks, unvalidated file inclusion, and disk leakage during data purging.

## 2. Path Traversal Mitigation in Static Serving

The embedded server (`ui/server.py: _serve_static()`) is responsible for delivering client assets (HTML, CSS, JavaScript, icons, audio prompts):

### 2.1 Canonical Path Validation
To prevent directory traversal attacks (such as `GET /../../../../Windows/win.ini` or `GET /..%2f..%2fetc%2fpasswd`):
```python
clean_path = path.lstrip("/").split("?")[0]
if not clean_path:
    clean_path = "index.html"

# Resolve absolute path and canonical directory boundary
static_dir = os.path.realpath(os.path.join(os.path.dirname(__file__), "static"))
target_file = os.path.realpath(os.path.join(static_dir, clean_path))

# Enforce containment within static directory
if os.path.commonpath([static_dir, target_file]) != static_dir:
    self.send_error(404, "File Not Found")
    return
```
- Both paths are canonicalized via `os.path.realpath()`, resolving all symbolic links and relative path tokens (`..`, `.`).
- `os.path.commonpath()` strictly verifies that the target file resides within the permitted `static` directory.
- Any request escaping the static boundary returns **HTTP 404 Not Found**, with zero leakage of server filesystem contents.

### 2.2 Test Verification
Automated test suite `tests/test_server_api.py: test_path_traversal_prevention()` continuously validates that URL-encoded traversal payloads (`..%2f..%2f..%2f..%2fWindows%2fwin.ini`) are rejected with HTTP 404.

## 3. Audio Asset & Recording Security

Speaking exam recordings and listening stimulus tracks are managed under strict isolation:

### 3.1 Filename & Reference Sanitization
- Speaking recording references generated by the application utilize cryptographically random identifiers (e.g., `speaking_rec_0a9b8c7d.wav`).
- Raw user-provided filenames are rejected; files are stored using server-controlledUUIDs.

### 3.2 Physical Cleanup upon Erasure
In `core/benchmark/benchmark_manager.py: withdraw_consent()`:
- When a candidate exercises their right to erasure, the recording path stored in `benchmark_records.recording_ref` is verified.
- The system checks that the file path is absolute, resides in an allowed data directory, and exists on disk.
- If verified, the file is permanently unlinked via `os.remove()`, preventing orphaned audio artifacts from lingering in storage.

## 4. Temporary File Governance

1. All temporary files generated during test runs (e.g., temporary SQLite databases, mock audio recordings) use Python's standard `tempfile.NamedTemporaryFile` in system-designated temp folders.
2. Automated test classes implement explicit `tearDown` or `tearDownClass` handlers with `try/finally` blocks to guarantee immediate deletion upon test completion.
